## 2. Verdict

**No. Hold architecture sign-off.** Phase 0 can proceed as a disposable spike, but its current success criteria can pass a happy path while missing failures that violate D13, D14, D16 or D18. The simulation-only wheel needs a wider build patch than described. The timing recipe fails on stock rc9 with a timer or an exhausted feed. Logout, upgrade, and terminal sealing need protocols that survive the tested failure modes. Bind service authentication to the connection carrying credentials. Revise those contracts and Phase 0's Go criteria, then require evidence from the restricted artifact and installed package before accepting the ADRs.

### Outbox, terminal ownership and sealing (D18)

- **[verified]** SQLite supports atomic writes inside each database, WAL `synchronous=FULL` syncs the WAL at commit, and online backup snapshots a running database. WAL gives atomicity per separate database; it supplies no transaction spanning the approval, journal and engine. Set `FULL` on every writer connection, including takeover, and verify the shipped library. The disposable CPython returned SQLite 3.53.1 via `python -I -c 'import sqlite3; print(sqlite3.sqlite_version)'`. **[unverified]** The actual package's power-loss behavior. [SQLite synchronous modes](https://www.sqlite.org/pragma.html#pragma_synchronous) · [WAL](https://www.sqlite.org/wal.html) · [Backup API](https://www.sqlite.org/backup.html)
- **[unverified]** The protocol is implementable with more states. A retry of an already receipted ID must be a lookup even after dispatch expiry. Expiry must stop new acceptance while preserving a way to distinguish undelivered from accepted with a lost acknowledgement. Validate ID, generation, payload, expiry and authorization at first admission. Persist command-specific refusal and progress, including partial fill and cancel, and define which event actually resolves each receipt. Store the approval/actor/reason binding and the corresponding cash and position changes in the journal for D1 exports. Recover missed committed publications from durable IDs after gateway loss, including worker commits made while it was down. [Overview §7 sequence](overview.md#paper-sessions-d1)
- **[contradicted]** A lock is not released merely because the original worker dies if a descendant inherited its open file description. A replaced lock path also gives a different inode and a second lock. In a disposable `fcntl.flock` fixture, `Popen(pass_fds=…)` kept the original lock held after the parent closed its descriptor, and recreating the path allowed a second exclusive lock. Keep a stable persistent lock inode and prevent inheritance. Verify unit identity and state plus journal generation under the lease, including the start window before a worker acquires it. Define recovery for an intent with no journal or no started worker. [Linux flock](https://man7.org/linux/man-pages/man2/flock.2.html) · [Overview launch intent](overview.md#responsibilities)
- **[unverified]** Exactly-once finalization requires a unique terminal record and seal in one journal transaction under the lease, and idempotent repair of the `app.db` status and copied head after restart. A trigger applies to specific operations and tables. A disposable `sqlite3` test using `BEFORE INSERT … RAISE(ABORT,'sealed')` blocked inserts and still allowed updates. Guard all ledger mutations, including the seal metadata. Persistent `SQLITE_FULL` can also prevent takeover from writing. Keep the session fenced and report finalization pending or reserve writable capacity. Never report a committed terminal state before it exists. [SQLite triggers](https://www.sqlite.org/lang_createtrigger.html) · [SQLite result codes](https://www.sqlite.org/rescode.html#full)

### Loopback identity, WebSocket tickets and Tauri (ADR-016/017)

- **[verified]** HMAC-SHA256 with a fresh nonce and a private key can authenticate a response. **[contradicted]** As specified, it does not prove the TCP listener receiving the bearer possesses that key. A listener that forwards the nonce to the genuine service can relay its valid response. The MAC does not authenticate the channel carrying the subsequent bearer, including the webview's separate connection. Bind authentication to the credential-bearing channel or use OS-authenticated local IPC and a narrow native bridge. Specify canonical message encoding, instance/version binding, constant-time comparison and key/nonce lifecycle. Test a relaying listener as well as one that simply lacks the key. This concerns the endpoint boundary within D2's stated threat model. [RFC 2104](https://www.rfc-editor.org/rfc/rfc2104) · [Overview §4 identity sequence](overview.md#4-desktop-shell-service-lifecycle-and-packaging)
- **[verified]** The browser constructor exposes subprotocols and no custom headers. The proposed header can carry an opaque token with legal subprotocol characters, for example unpadded base64url. Offer a fixed application protocol and a ticket value, then select only the fixed protocol in the response. Consume the ticket atomically before upgrade after checking origin, Host, epoch, expiry and the issuer's scopes and subscription authority. Redact the request header and define what grant revocation and rotation do to an open stream. **[unverified]** Installed ticket issuance and retry, a simultaneous double redemption, cross-origin/scope denials, expiry, opaque-origin fallback and exact CSP for both HTTP and WebSocket. [WHATWG WebSocket interface](https://websockets.spec.whatwg.org/#the-websocket-interface) · [RFC 6455 handshake](https://www.rfc-editor.org/rfc/rfc6455#section-4.1)
- **[verified]** `AppManifest::commands` brings application commands into permission checks. Tauri 2.12.7 exposes `on_navigation` and `on_new_window`. The allowlist must retain bundled navigation, and capability grants are additive across matching capabilities. Verify denied calls from detached windows as well as allowed calls from main. **[unverified]** Packaged navigation hooks, actual HTTP and WebSocket `Origin` values and the delivery of a port-specific CSP before web content loads. A Tauri bundle URL in upstream tests establishes the URL, with the emitted network Origin still to be observed. Specify how CSP uses the new port on service restart. Spell out `http://` and `ws://` sources separately. [Tauri capabilities](https://v2.tauri.app/security/capabilities/) · [Tagged webview hooks](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.7/crates/tauri/src/webview/mod.rs#L506-L601) · [Tauri CSP](https://v2.tauri.app/security/csp/)

### Static strategy validation (ADR-005/010)

- **[verified]** `ast.parse` parses without importing, and a subsequent compile without execution can catch errors beyond parsing. An import-node allowlist can enforce the syntax of declared imports and selected direct base classes. **[contradicted]** It cannot establish an arbitrary Python file's actual dependency closure or count its runtime subclasses. Python supports programmatic imports and dynamic class construction, and decorators and module code run when loaded. ## 5. New findings

### P0

1. **The engine artifact recipe cannot deliver the stated build as written.** ADR-002 and 0A need the native registration and maturin changes in §4. The Go line's “or P1 is decided otherwise” must mean a conforming artifact approved under D13. [0A and Go](desktop-validation.md#go--no-go)
2. **The timing proof can bless an order filled on stale signal data.** Add the timer and EOF counterexamples to 0A, require the paper implementation to pass its own first-eligible-event test, and define feed-event attribution and the FIFO projection in ADR-013. A later fill timestamp alone cannot satisfy D14. [Overview §7 Backtests](overview.md#backtests)
3. **Version switching and logout are described as outcomes without the transitions that produce them.** Establish a real pre-unpack or retained-payload upgrade protocol. For logout, specify and test bounded worker drain independently of gateway availability. Reconcile “any restart” in §1 and “Never rely on signals” in §11 with the actual choices. [Overview §§1, 4 and 11](overview.md#4-desktop-shell-service-lifecycle-and-packaging)
4. **The terminal protocol has a second crash window.** Separate append and seal steps can leave a terminal row in a writable journal, and a previous generation match alone cannot disambiguate a launch still in progress. Commit the seal with the unique terminal record, fence launch against takeover and test failures between journal commit and `app.db` repair. [Overview §7 paper sessions](overview.md#paper-sessions-d1)
