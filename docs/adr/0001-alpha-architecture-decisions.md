| ID | Decision | Alternatives and consequences | Acceptance evidence |
|---|---|---|---|
| ADR-001 | **Runtime ownership.** Tauri 2 (2.12.x) Rust shell, shared React/TS UI, Python 3.13 / FastAPI service. Shell, CLI, MCP and desktop share the same application services. Rust only in the shell and inside Nautilus's own core. | A browser-only product conflicts with the product direction. A Rust trading service would duplicate the engine. | 0B–0D pass. One shared client contract. Desktop E2E through `tauri-driver`. |
| ADR-002 | **Engine (D1, D13).** NautilusTrader v2 (`2.0.0rc9`), pinned exactly. A **simulation-only build** from the exact tag. The patch: (1) replaces the default `adapters` umbrella with per-adapter features, enabling only sandbox and Databento; (2) changes the native registration guards in `crates/pyo3/src/lib.rs` to match; (3) removes the maturin features `defi`, `hypersync`, `redis` and `postgres`; (4) prunes the excluded Python adapter packages and their `.pyi` stubs. Provenance recorded; source provided as the LGPL requires. | Changing the feature list alone either fails to build or drops the sandbox registration (Codex). If the build proves infeasible, escalate; do not relax D1. Propose per-adapter features upstream. | `cargo tree -e features` with the wheel's flags. Wheel manifest and native-module inspection: only the sandbox execution factory; Databento imports. Clean-install smoke tests. |
| ADR-003 | **Storage.** The v2 catalog is canonical. Manifests list exact files. `app.db` uses WAL with `synchronous=FULL` on every connection, has a single writer, and holds a **change log**. Each session has its own journal, also at `FULL`. No DuckDB, Polars or pandas. | `NORMAL` can lose committed transactions. | Round-trip test; reads limited to manifest files; online backup and restore; migrations. |
| ADR-004 | **Workers.** One node per process, as transient systemd user units pinned to a runtime by absolute path. Launch intents go `starting` → `running` → `ended`. Lease files keep a stable inode, are opened `O_CLOEXEC`, and are never passed to child processes. Adoption verifies `InvocationID`, the lease and the generation. Everything sits behind a `WorkerLauncher` interface. | Workers tied to the service process die with it. `flock` survives in an inheriting child and is defeated by replacing the path (Codex). | Adoption after a service restart; takeover of an intent stuck in `starting`; refusal when the lock path is replaced or a descriptor is inherited. |
| ADR-005 | **Strategies.** A narrow single-module form, snapshotted as exact bytes (`openat2` beneath the staged root, no symlinks, regular files only). **Structural** validation only: `ast.parse` plus `compile`, no import, form rules. The **canonical config and named inputs** are bound to each run. Runs import with `python -I` and a restricted `sys.path`. No editor (D9). | An AST allowlist cannot prove the full set of runtime dependencies. Trust comes from the human acknowledgement. Multi-file bundles come later. | Tests: content changed between registration and launch, symlinks, paths outside the root, dynamic imports, constructs outside the form. |
| ADR-006 | **MCP** (D4, D8). SDK v2 over stdio. Host configuration is `/usr/bin/clipper-mcp --grant-file …`, with no token in it. **The principal is the grant's client ID**, and rotation keeps the principal. One capability matrix, enforced in the shared layer for MCP, REST, stream tickets and result IDs. Revocation closes streams. Never available to MCP: approve, acknowledge, take control, cancel, flatten, re-enable, change policy, manage grants. | A shared token over-grants. Tool discovery does not establish identity. | Invocation and denial tests for every grant and surface; rotation while connected; jobs survive the host exiting. |
| ADR-007 | **Phased authorization (D2).** A versioned approval envelope bound to the controller's principal and login session. MCP only prepares intents. Stronger tiers later need protected enrollment, verifier and confirmation display. | Strong authorization now would delay alpha. | Expiry, replay, tampering, cross-session, MCP and non-controller refusals; red-team record. |
| ADR-008 | **Paper durability (D18).** <ul><li>An outbox, with expiry that never turns a lost acknowledgement into "undelivered". A receipted command ID is always a lookup.</li><li>Admission checks. Receipts store the **approval binding**. Per-command progress names its resolving event.</li><li>The outcome, projection, cash and position changes and attribution are written in one transaction.</li><li>Durable last-published event IDs, and replay after a gateway outage.</li><li>**The terminal record and the seal row are one transaction** under the lease, with a `UNIQUE` terminal key. Seal triggers block INSERT, UPDATE and DELETE on every ledger table.</li><li>A reserved block for the terminal write. `finalization_pending` if that still fails. Idempotent repair of `app.db`.</li></ul> | Appending the terminal record and sealing as separate steps leaves a crash window. A trigger on INSERT only still allowed updates (Codex). | Fault suite: kills at every boundary, expiry after a lost receipt, a gateway outage while the worker commits, disk full, power loss (VM), a crash between the journal commit and the `app.db` repair. Exactly one terminal record. A sealed journal refuses every mutation. |
| ADR-009 | **Charts and workspace.** Lightweight Charts 5.3 and its official plugins. Docked layout first, then detached windows. Workspace state lives in the service, with revisions and a change log. Indicators are computed in the service. | — | Performance (D26) inside the webview under XWayland; detach and restore; accessibility; attribution. |
| ADR-010 | **Strategy trust.** An acknowledged snapshot runs with the worker's full permissions, and the docs say so. No OS sandbox in alpha. Decide where the feed client runs before stage-2 credentials. | Local sandboxing adds nothing against a same-user agent. | Refusal without acknowledgement; residual risk published. |
| ADR-011 | **Licensing (D3, D20).** AGPL core; Cloud separate. **NautilusTrader stays replaceable:** one launcher picks the shipped engine or a user override, and uses the same choice for the service and both worker types, never mixing them. Compatibility is checked by interface version. Manifests record the engine build actually used. The artifact gate applies only to the shipped artifact. Source is published only as the licences require. Maintainer and legal review before every release. | A lockfile inventory misses bundled binaries. A plain wheel alone doesn't settle LGPL §4. | Release evidence inventory; a visibly modified engine runs through backtest and sandbox, before and after an upgrade; sign-offs. |
| ADR-012 | **Data (D5, D19, D25).** US equities and ETFs, daily and minute bars, free data first; Databento leads for stage 2. **Phase 0 fixtures are synthetic OHLCV bars plus bid/ask quotes, with provenance** (generator, seed, version, declared corporate-action coverage). Every dataset declares its corporate-action source and coverage. Market data is stored or exported **only where the licence allows**; otherwise it is withheld and flagged. **Approved exports pass an export filter.** Raw backups are for recovery only. | A paid feed on the critical path would block development. Local retention rights are not export rights. | Provider matrix: cost, terms, retention, export, corporate actions, bar-to-live equivalence. Export-filter tests. Fixture provenance recorded. |
| ADR-013 | **Financial truth (D14, D22).** `after_watermark`: an order matches only against a book update derived from a new feed event for its own instrument, with `ts_init` after the decision watermark. Phase 0 tests two mechanisms: **(a) a native, upstream-supported configuration (preferred)**, and **(b) a Clipper gate on the matching path**. Counterexample suite: timers, end of feed, equal timestamps, other instruments, first-update order, stale feed, resting orders, partial fills. The synthetic bid/ask quotes (D25) exercise first-event matching. Every fill carries an attribution record. The **FIFO lot projection** is the record; quantities and cash reconcile with the engine. Fee specification has an order-level minimum and cap, and effective-dated fees. Splits **and unknown coverage** fail closed. | Latency alone fails on stock rc9 because of timers and the end-of-run drain (Codex). rc9 fills carry no feed reference, and rc9 allocates cost proportionally. | Independent ledgers through the packaged backtest and replay sandbox; the counterexample suite passes under the chosen mechanism; FIFO fixture (FIFO 20 against the engine's 15). |
| ADR-014 | **Contributor licensing.** A CLA before the first external merge, after legal review. DCO stays. | — | Counsel-approved text and tooling. |
| ADR-015 | **Local threat model.** Same-user agents, including via Docker and X11, are inside the trust boundary. The audit chain is a local integrity check only; a consistent rewrite passes. Unix-socket peer checks stop only other users. | — | Threat model published; audit tests; red-team record. |
| ADR-016 | **Lifecycle and channels.** **Native clients use a Unix socket with a peer-UID check.** The webview learns its loopback port over that socket, and the service holds the port without `SO_REUSEPORT`. Webview REST uses a short-lived bearer. WebSocket uses single-use tickets in a subprotocol, consumed before the upgrade. The shell serves the CSP with the current port. **Logout (D16, D24):** a logind watcher follows each controller's login and triggers a 30 s IPC drain (also run from `ExecStop`), then a supervised stop (`TimeoutStopSec=30`) and takeover as `interrupted`. Signals are only the supervisor's fallback. | A relaying listener can pass an HMAC challenge, so it was dropped. `PartOf=` stops units without draining them. Reboot gives only a short inhibitor window. | A relay listener cannot get credentials; a wrong-UID peer is refused; logout with working orders and queued commands; forced timeout; gateway down during logout; reboot. |
| ADR-017 | **Packaging and display (D11, D23).** **Side-by-side** `clipper-runtime-<version>` packages under `/opt/clipper/<version>/`, each built at its final path, plus a `clipper` package with the shell, launchers and units. A new runtime is activated through an admission fence and a state file. Workers stay pinned to their runtime. `prerm` refuses removal while a runtime is in use; `clipper runtime prune` cleans up. **XWayland first** (D7, D17): escalate if it fails; Wayland is a diagnostic only; CEF only at the maintainer's direction. | One package with versioned directories removed the old files on upgrade (Codex). | Two-version upgrade with an active worker; deferred activation; prune; removal refused while in use; clean install and offline launch; display and GPU matrix. |
| ADR-018 | **Windows later.** Interfaces for the native channel (named pipe with an ACL for the user's SID), service manager, worker supervisor (holding the Job Object handle), login watcher (WTS), locks, paths, webview origin, packaging and stop. | — | Portability review; a Windows spike before Windows is scheduled. |
| ADR-019 | **Session controller (D24).** Exactly one controller per local paper session: a human principal bound to a logind session. Only the controller can approve, cancel, flatten, re-enable, stop or end the session. Control moves only by explicit release or take; each transfer is journalled and invalidates pending approvals. Other windows and logins are read-only. The session's lifetime follows the controller's login. MCP is never the controller; `paper:halt` works without control. | With no controller, two logins could act at once and "logout" would be ambiguous. | Tests: two logins, transfer while an approval is pending, logout by a non-controller, logout by the controller, refusal of a non-controller's actions. |
| ADR-020 | **Initial performance and memory targets (D26).** Chart pan and zoom: **≥ 30 FPS sustained, target 60**. **Desktop memory < 1 GB** total PSS for the shell, all webview processes and the Clipper service. **NautilusTrader worker memory is measured separately** and its peak reported; no limit yet. These are initial targets. | Setting limits before measuring would be guesswork. | Phase 0 protocol (overview §10) on the reference machine under XWayland. |
