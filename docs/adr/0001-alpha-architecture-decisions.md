| ID | Decision | Alternatives and consequences | Acceptance evidence |
|---|---|---|---|
| ADR-001 | **Runtime ownership.** Tauri 2 (2.12.x) Rust shell, shared React/TS UI, Python 3.13 / FastAPI local service. CLI, MCP and desktop share one set of application services. Rust only in the shell and inside Nautilus's own core; no Nautilus crates linked into the shell. | Browser-only conflicts with the product direction. A Rust trading service would duplicate the engine and create static LGPL linking. Tauri 3 is in alpha, so keep the shell thin. | Phase 0 proofs 0B–0C pass; one shared OpenAPI client; desktop E2E through `tauri-driver`. |
| ADR-002 | **Engine:** NautilusTrader v2, exact pin (`2.0.0rc9` today), CPython 3.13. Move to `2.0.0` final through one PR running the full fixture suite. **Artifact gate (D1):** ship a **simulation-only wheel** built from the exact upstream tag, with a small, auditable feature-list change (sandbox and databento only) and with excluded adapter modules removed. Record provenance; provide its source as the LGPL requires (D13, D20). D1 is not relaxed. | The ordinary rc9 wheel ships importable Binance and Interactive Brokers execution factories. Upstream has one `adapters` feature for everything. Maintain the build patch and propose per-adapter features upstream. If the build proves infeasible, escalate to the maintainer; amending D1 is not a fallback (D13). v1 is legacy. | Inspection of the wheel and native module shows only the sandbox execution factory. Backtest and sandbox smoke tests pass from a clean install. Provenance recorded. |
| ADR-003 | **Storage.** The Nautilus v2 catalog is canonical, with immutable manifests that list exact files. `app.db` (WAL, `synchronous=FULL`, single writer). One journal per session (WAL, `FULL`). No DuckDB or Polars, and no pandas: results come from a typed event projection, not Nautilus's report helpers. | `NORMAL` can lose committed transactions on power loss. Report helpers would add a pandas dependency. | Round-trip with checksums; reads limited to manifest files; online backup and restore; migrations. |
| ADR-004 | **Workers.** One engine node per worker process, as transient systemd user units with cgroup limits. A **launch intent** (session, generation, unit) is persisted before start, so a restarted service can adopt surviving workers. Workers sit behind a `WorkerLauncher` interface covering ownership, fencing, timeouts, cancellation and adoption. | Running several nodes in one process is unsupported upstream. Workers tied to the service process would stop on restart. | Parallel jobs; enforced limits; a worker survives a service restart and is adopted; mixed-version workers are refused. |
| ADR-005 | **Strategies.** Python strategies, as **self-contained single files**, snapshotted by content hash and validated statically (AST, no import, allowlisted imports, no symlinks or paths outside the root). Runs always use the snapshot. No Pine; no editor (D9). | Multi-file bundles with an import manifest are a later option. Importing a file to validate it would execute it. | Tests for changed content, paths outside the root, symlinks and modified imports. The same snapshot runs in backtest and paper. |
| ADR-006 | **MCP** is the primary AI control interface (D8) and comes first (D4). SDK v2 (`mcp>=2.3,<3`) over stdio, launched by absolute path. **Per-client grants** minted by the human through the CLI, rotatable and revocable. Actors derived on the server. Published capability matrix (overview §8). Approval, acknowledgement, cancel, flatten, re-enable, policy and grant management are never grantable to MCP. | A shared token over-grants. Tool discovery does not establish who the principal is. Remote MCP is deferred to Cloud. | Claude Code and Codex at their negotiated protocol versions; invocation tests for every grant; denial tests; jobs survive the host exiting; telemetry scrubbed. |
| ADR-007 | **Phased authorization (D2).** Alpha: human approval in the desktop or CLI, bound to a digest in a **versioned approval envelope** (intent, session, actor, policy revision, expiry, evidence type), single-use. MCP prepares intents only. Future: proof of human presence, plus protected enrollment, verifier, policy storage and confirmation display. | Strong authorization now would delay alpha. A WebAuthn assertion alone does not prove which trade was displayed. | Expiry, replay, tampering, cross-session and MCP-refusal tests. A red-team record of which paths outside MCP still work in alpha. |
| ADR-008 | **Paper durability (D1).** Approval is consumed and enqueued in an `app.db` outbox in one transaction. Worker receipts are idempotent by command ID and digest. Each engine outcome is committed with its projection. Events are published only after commit. Everything runs at `synchronous=FULL`. The lease is a `flock` on a separate lock file. **Terminal takeover:** the service acquires a dead worker's lease, verifies its generation, appends exactly one `interrupted` record, and seals the journal. A journal write failure freezes the session. Cache database backing is forbidden. Resume is deferred. | Unique keys alone do not cover the boundaries between delivery, engine and storage. A dead worker cannot write its own end. A record owned only by the service would split the ledger. | Fault tests at every boundary: lost and concurrent retries, a gateway restart while a worker lives, disk full, `kill -9`, abrupt power loss (VM). Exactly one terminal record. Sealed journals refuse writes. |
| ADR-009 | **Charts and workspace.** Lightweight Charts 5.3 and its official plugins; one shared React UI. Docked first, then detachable windows. Workspace state lives in the service, with revisions. Indicators are computed in the service. | A custom renderer is unnecessary. Indicators computed in JS would diverge from what the agent sees. | Performance inside the webview under XWayland; detach and restore; accessibility; attribution. |
| ADR-010 | **Strategy trust.** A strategy is trusted when it is an acknowledged snapshot (ADR-005). It runs with the worker's full permissions, which is recorded. No OS sandbox in alpha, and the launcher is the seam for adding one. Before stage-2 credentials, decide where the feed client lives. | Local sandboxing gives no protection against a same-user agent. | Refusal without acknowledgement; residual risk published. |
| ADR-011 | **Licensing.** AGPL-3.0-or-later core (D3); Cloud separate and possibly proprietary. **Release evidence:** exact payload inventory (CPython and its native libraries, wheels, crates, npm, chart assets), checksums, a source/rebuild mapping and notices. Source is published only as the applicable licences require, as determined by legal review (D20). **LGPL path:** a tested engine-override mechanism that persists across upgrades, so NautilusTrader stays replaceable (D20). **Every release needs maintainer and legal review.** | A lockfile inventory alone misses bundled binaries. Leaving the engine as an ordinary wheel does not satisfy LGPL §4 by itself. | Inventory generated in CI; override tested after a clean install; maintainer and legal sign-off before each release. |
| ADR-012 | **Data.** US equities and ETFs, daily and minute bars, free data first (D5). Databento is the leading candidate for stage 2. Retention under the provider licence is decided per provider; the journal flags data it did not retain (D19). | A paid feed on the critical path would block development. | Provider matrix covering cost, terms, retention, and equivalence of bars and live data. Terms-of-service check for every source. |
| ADR-013 | **Financial truth.** Default execution timing **`after_watermark`**: an order fills on the first eligible matching event after the decision's data watermark. It is implemented with a positive latency specification and the finest execution data available; with bars only, that is the next bar's close, and results are labelled that way. `signal_close` is available only as a named, labelled option (D14). Fee schedule from a published broker schedule; FIFO cost basis. Versioned fee, fill and latency **specifications**, each instantiated per process. Order-level fee minimum and cap across fills. Section 31 fees by effective date; TAF separate. Splits fail closed. Calendar and instrument metadata are pinned. | With zero latency, Nautilus settles at the close the strategy just observed, and it has no next-bar-open mode. Repeatable results prove repeatability, not plausibility. | An independently calculated expected ledger run through the **packaged** backtest and replay sandbox, covering callback timing, partial fills, cost basis, P&L, insufficient cash, competing stop and target orders, split refusal, half days and DST. |
| ADR-014 | **Contributor licensing.** A CLA is required before the first external contribution, with counsel reviewing it first and a merge hold until then. DCO sign-off stays. | Inbound=outbound alone would block proprietary use of outside contributions. | Counsel-approved text; signing tooling chosen; link in `CONTRIBUTING.md`. |
| ADR-015 | **Local threat model.** Agents running as the same user, including through Docker group access and X11 input injection, are inside the OS trust boundary. The hash-linked audit is a local integrity check only: a consistent rewrite passes, and the docs disclose that. | OS user separation doesn't help while group membership makes agents root-equivalent. | Threat model published; audit tests for row edits, truncation and consistent rewrite; red-team results. |
| ADR-016 | **Lifecycle.** The shell presents the UI; the systemd user unit owns lifetime. No sidecars and no `tauri-plugin-shell`. The service proves its **identity with an HMAC challenge** before any bearer token is sent. The WebSocket authenticates with **single-use stream tickets** sent through `Sec-WebSocket-Protocol`. "Stop service" means a native confirmation, then the service's own drain. **Versioned prefixes**, so upgrades never replace files under a running worker. **Logout ends local paper sessions** through `PartOf=graphical-session.target`: open orders are cancelled and the history is preserved. **Upgrades wait until sessions have stopped** (D16). Running sessions independently of a login is future Cloud scope. | Sidecars die on a normal exit. A token sent to an unverified port would leak to a spoofed listener. Browsers can't set WebSocket headers. | Installed-package tests: authenticated reads, writes and subscriptions; spoof rejection; concurrent clients; token rotation; close, reopen and crash; upgrade with an active worker; logout. |
| ADR-017 | **Packaging and display.** One `.deb` (D11): the shell plus `/opt/clipper/<version>/`, holding CPython 3.13 and an environment built **at its final path** from locked, non-editable wheels. No relocation. Build paths and ELF dependencies verified. Ubuntu 22.04 build base. XWayland default (D7), and detached-window restore must pass there. Native Wayland is secondary. XWayland is the priority mode. If it fails, **escalate to the maintainer**; CEF or Wayland are tried only at the maintainer's direction (D17, narrowing D10). | `uv venv --relocatable` left links pointing at the staging path (as Codex reproduced). A frozen binary weakens the LGPL replacement path. | Clean install on the reference machine, offline launch, upgrade and uninstall with active work; display and GPU matrix. |
| ADR-018 | **Windows later.** Platform-specific code sits behind interfaces: service manager, worker launcher (including a future supervisor that holds the Job Object handle across gateway restarts), command transport (named pipes with an ACL for the user's SID), locks, paths, webview origin, and the engine build. | Ignoring Windows now would bake systemd and Unix sockets into the core. | Portability rules (overview §11) reviewed; Windows build spike before Windows is scheduled. |

## Decisions on the pending items

The Codex review's open questions P1–P8 were decided on 2026-11-25. The full
text is in [`maintainer-decisions.md`](../architecture/maintainer-decisions.md).

| ID | Decision |
|---|---|
| P1 | **D13:** D1 is not relaxed. A simulation-only engine build from the exact upstream tag. If that proves infeasible, escalate to the maintainer. |
| P2 | **D14:** `after_watermark` default; `signal_close` as a labelled option. Configurable broker fee specification; FIFO cost basis; splits fail closed. |
| P3 | **D15:** MCP `paper:halt` only. Cancel, flatten and re-enable are human-only. |
| P4 | **D16:** logout ends the local paper session, cancels open orders and preserves history. Upgrades wait until sessions have stopped. Cloud may run sessions independently later. |
| P5 | **D17:** XWayland first. On failure, escalate to the maintainer before evaluating CEF or Wayland. |
| P6 | **D18:** three published states, each after its commit. The worker writes the terminal record on a clean end; the service writes it through fenced takeover on interruption. |
| P7 | **D19:** retain driving data only where the licence allows, and flag it otherwise. |
| P8 | **D20:** NautilusTrader stays replaceable. Source is published only as the applicable licences require. Maintainer and legal review before every release. |
| — | **D21:** alpha documents name no specific orchestration product; the generic term is "external AI orchestration tools". |

## Review protocol

- **Reviews so far:** Claude reviews 1 and 2 (with errata) and the
  independent Codex review (D12).
- **This revision** was written by Claude to fix the Codex findings. Codex
  should confirm the fixes before sign-off.
- **Next steps:** Codex confirms revision 3.1, then Phase 0 runs. ADRs are
  accepted on the evidence, and only then is the backlog created.
- No implementation happens under issue #1.
